Public API

This page lists the public surface of BlobBoards.jl. Exported names are listed bare; public (supported, unexported) names are listed qualified and are reached as BlobBoards.name.

Pattern Generation

BlobBoards.blob_pattern — Function
blob_pattern(config::PatternConfig; dir=nothing)

Generate a deterministic blob pattern from a PatternConfig. RNG is MersenneTwister(config.seed) for reproducible output.

Returns (pattern, blobs) where pattern is the rendered image and blobs is a vector of placed blobs. If dir is provided, saves the pattern as PNG with JSON sidecar.

source
blob_pattern(pixel_type::Type, pattern_resolution::Size2; kwargs...)

Generate a blob pattern with specified pixel type and resolution.

Arguments

  • pixel_type: Output pixel type (e.g., Gray{Float64}, Gray{N0f16})
  • pattern_resolution: Pattern size as Size2 with logical units

Keyword Arguments

  • blob_sizes: (min, max) blob sizes in logical units (3px; a bare number is px). max may be 0.2short_side (a fraction of the short side) or nothing (default: diameter = 20% of the short side). Default (2px, nothing).
  • blob_measure: what blob_sizes measures — :sigma (default), :radius (cutoff·σ, the rendered disc) or :diameter (2·cutoff·σ). Sizes are stored as σ in px (min_scale, max_scale), both exact; the sizes between are spaced evenly in log at about 1/scales_per_octave octave (see calc_blob_scales).
  • seed: Random seed for reproducible patterns
  • scales_per_octave: Number of scales per octave (default 3)
  • α: Scale sampling bias (default 1.2)
  • cutoff: Gaussian truncation radius multiplier (in units of σ, required)
  • max_trials: Maximum placement trials per blob (default 5000)
  • raster_aligned: Align blob centers to raster grid (default true)
  • polarity: Blob polarity, :dark (default) or :light
  • dir: Output directory for saving files (optional)

Returns (pattern, blobs, config).

source

BlobBoards.short_side — Constant
short_side

Marker for a size relative to the pattern's short side: 0.2short_side is 20% of it. Valid as the MAX of blob_sizes, a disc diameter like any other size (blob_sizes = (2mm, 0.2short_side) makes the largest disc's diameter 20% of the short side).

source
BlobBoards.ShortSideFraction — Type
ShortSideFraction(fraction)

A size given as a fraction of the pattern's short side — what fraction * short_side builds. Resolved to px once the pattern size is known; never stored.

source
BlobBoards.calc_blob_scales — Function
calc_blob_scales(min_scale, max_scale; scales_per_octave = 3) -> Vector

The blob-scale ladder from min_scale to max_scale, both exact: k + 1 scales, k the whole number of 1/scales_per_octave-octave steps nearest the span, spaced evenly in log. When max_scale lies on the 2^(1/scales_per_octave) ladder the scales are exactly min_scale · 2^(i / scales_per_octave). Unitless px.

Board Generation

BlobBoards.blob_board — Function
blob_board(paper_size::String, print_density; kwargs...) -> BoardBundle
blob_board(width, height, print_density; kwargs...) -> BoardBundle
blob_board(canvas_size::Size2, print_density; kwargs...) -> BoardBundle
blob_board(pixel_type, paper_size | width, height | canvas_size, print_density; kwargs...)
blob_board(json_config::String; dir, format, pdf_standard, icc_profile, id_label) -> BoardBundle
blob_board(preamble::BoardPreamble, board_sizes::LogicalBoardSizes;
           dir, format, pdf_standard, icc_profile, id_label) -> BoardBundle

Generate a printable calibration board (blob pattern, ruler frame, QR code and uid corners) at an exact physical size, and optionally write the print file and its JSON.

Sizes are physical (mm, inch) and print_density is a density (300dpi); the pattern is rasterized at that density, one pattern pixel per printer dot. Requires using CairoMakie (it loads BlobBoardsAuthoringExt); format = "tiff" also needs using Libtiff_jll.

Arguments

  • paper_size: a key of BlobBoards.PRINT_SIZES — "A0"…"A5", "ANSI A"…"ANSI E1", "Letter", "US Letter", "Legal", "Tabloid", "Ledger" (portrait, except "Ledger"). Anything else is an ArgumentError.
  • width, height or canvas_size = Size2(width = …, height = …): the page (canvas) size, physical lengths.
  • print_density: the print resolution, e.g. 300dpi.
  • pixel_type (optional, leading): the pattern's pixel type, e.g. Gray{N0f16} (default Gray{N0f8}). It is positional only — pixel_type = … as a keyword is an ArgumentError.
  • json_config: the text of a board JSON sidecar; re-generates that board bit-exactly from its stored configuration (placement is re-run from the seed), under its stored identity (hashes.config: same uid and file name). The output keywords default to the JSON's render block, how the sheet was printed (a file without one: PDF/X-4, no id label); a keyword overrides it. The sidecar is written in the current schema, and the QR encodes the same preamble.
  • preamble, board_sizes: the low-level form the others reduce to — a complete BlobBoards.BoardPreamble and its BlobBoards.LogicalBoardSizes.

Keywords

The paper-size, width/height and Size2 forms (and their pixel_type variants) take every keyword below; the JSON and preamble forms take the Output group only. A keyword outside this list is an ArgumentError, never silently ignored.

Output (validated before placement)

  • dir = nothing: output directory, created if missing. Writes blob_board_<uid>.<format> and blob_board_<uid>.json (the sidecar that reproduces the board), overwriting. nothing writes no file and only returns the bundle; giving format, pdf_standard, icc_profile or id_label without a dir is then an ArgumentError. The JSON also records, outside the board's identity, how the file was rendered (its render block).
  • format = "pdf": "pdf" — the print master (vector frame, pattern embedded pixel for pixel, lossless, rewritten by Ghostscript to pdf_standard; PDF/X-4 needs Ghostscript ≥ 10.07); "tiff" (or "tif") — the whole sheet at exactly print_density, 8-bit grey, LZW, density in the resolution tags and the ICC profile embedded (needs using Libtiff_jll); "png" — single-channel grey, linear gamma, for digital use. Case-insensitive; anything else is an ArgumentError.
  • pdf_standard = :x4: :x4 (PDF/X-4, what most print shops ask for), :x3, :x1a (PDF 1.3, for older RIPs) or :none (a plain lossless PDF with no OutputIntent). "pdf" only: giving it with another format is an ArgumentError.
  • icc_profile = nothing: the grey profile declaring how the values print — nothing or :linear (linear reflectance, the default) or the path of a single-channel ICC file. Used as the PDF/X OutputIntent and embedded in a TIFF (which embeds the linear profile by default); giving it with "png" or with pdf_standard = :none is an ArgumentError.
  • id_label = true: print the board's identity (file stem, full config hash, BlobBoards version, size @ dpi) in one 6 pt line under the board, in the sheet margin outside the TrimBox. Skipped when the margin has no room (with a warning for a frameless board, which then carries no printed identity). A rendering option, not part of the identity.

Pattern (recorded in the board's PatternConfig; see blob_pattern)

  • blob_sizes = (4.0mm, nothing): the smallest and largest printed disc DIAMETER (2·cutoff·σ), physical lengths converted through print_density. max may be a length, a fraction of the pattern's short side (0.2short_side) or nothing (20% of the short side). The min may not be nothing or a fraction; its default is 2·cutoff·1mm (4 mm at the default cutoff). Both ends are exact. The smallest disc must be at least 2·cutoff·2 printer dots (σ ≥ 2 px: 0.68 mm at 300 dpi), reported in mm when violated, and the largest must be smaller than the pattern's short side. Stored as σ in px (min_scale, max_scale; those names are not keywords).
  • seed: the placement RNG seed (any integer; default a random UInt64, recorded in the bundle). Same seed and keywords → the same board.
  • polarity = :dark: :dark blobs on white or :light blobs on black.
  • scales_per_octave = 3: rungs per octave of the blob-scale ladder.
  • α = 1.2: scale-sampling bias (how many blobs each scale gets).
  • cutoff = 2.0 (DEFAULT_CUTOFF): the disc radius in σ; keep the default.
  • max_trials = 5000: placement attempts per blob before a scale gives up.

A board's blob centres always sit on pixel centres (raster_aligned is recorded as true in its PatternConfig and is not a keyword).

Board, frame and rulers (recorded in the board's BoardConfig)

  • board_size = canvas: the board area, a Size2 of lengths ≤ the canvas in both dimensions, centred on the page with white margins; the PDF TrimBox marks it.
  • frame_width = 0.075 · max(width, height): the frame band around the pattern; its square corners hold the QR code (top left; omitted with a warning when the encoded preamble does not fit the corner at this density) and the three uid characters. The pattern is board_size − 2·frame_width. 0mm gives a frameless board: the pattern fills the board, with no rulers, QR code or uid.
  • frame_style = :ruler: what fills the frame — :ruler (tick marks), :saddle (a two-row checkerboard; the bundle then carries its saddle points) or :none (blank, corners only).
  • frame_padding = 0mm: white inset between the frame's content (ticks, saddle squares, QR code, uid glyphs) and its edges; must be < frame_width / 2 unless frame_style = :none.
  • major_tick_spacing = 10mm, minor_tick_spacing = 5mm: ruler tick intervals. The ticks are centred along each side; check the printed scale against them.
  • major_tick_width = frame_width − 2·frame_padding, minor_tick_width = major_tick_width / 2: each tick's full drawn length across the frame band (physical units, centred in the band). The defaults fill the padded band with major ticks and draw minor ticks half as long. Requires 0 < minor_tick_width ≤ major_tick_width ≤ frame_width − 2·frame_padding, else an ArgumentError.

Never keywords: canvas_size, print_density, pattern_resolution (derived from the positional arguments), min_scale, max_scale (use blob_sizes), pixel_type (positional), raster_aligned, blob_measure (sizes are always diameters) and ruler_width (removed: set the tick widths) are each an ArgumentError.

Returns

A BlobBoards.BoardBundle:

  • bundle.preamble: the BoardConfig (board_config(bundle)) and PatternConfig (pattern_config(bundle)) — everything needed to re-generate the board; its hash is the uid printed in the corners.
  • bundle.blobs: the placed blobs (Discs, px, pattern frame); use blobs(bundle, frame; units) for :board, :canvas or :world coordinates, or mm.
  • bundle.saddle_points: the frame's saddle points (frame_style = :saddle only; empty otherwise), via saddle_points.

Examples

using BlobBoards, CairoMakie# An A4 board at 300 dpi, written as PDF/X-4 + JSONbundle = blob_board("A4", 300dpi; seed = 0xBEEF, dir = "./out")# A custom page, a 180 mm square board on it, 2–12 mm printed discsbundle = blob_board(200mm, 250mm, 600dpi;    board_size = Size2(width = 180mm, height = 180mm),    blob_sizes = (2mm, 12mm),    frame_style = :saddle, frame_padding = 1mm, dir = "./out")# 16-bit pattern, TIFF print master for a photo labusing Libtiff_jllbundle = blob_board(Gray{N0f16}, "A3", 1200dpi; format = "tiff", dir = "./out")# Re-generate a stored boardbundle = blob_board(read("./out/blob_board_abc_12345.json", String); dir = "./out2")

See also

blob_pattern (the pattern alone, in pixels), PatternConfig, BoardConfig, BlobBoards.PRINT_SIZES. BlobBoards.render_board re-renders a stored bundle without re-running placement.

Detection and Pose

find_boards is the entry point: it detects blobs, fits elliptical frames, canonicalizes patches, describes them, matches against a board gallery, and estimates pose. The camera lives inside config.geometry — PoseGeometry for the calibrated P3P path, HomographyGeometry for the uncalibrated one — so a camera/geometry mismatch is unrepresentable rather than a runtime error.

Adaptation is backend-generic (KernelAbstractions): device = KA.CPU() runs the threaded host implementation, CUDABackend() (or any KA GPU backend) the device kernels. Results agree to within the pipeline's own run-to-run jitter; CUDA additionally provides cuBLAS/libdevice fast paths.

BlobBoards.find_boards — Function
find_boards(board_feature_dict, descriptor_network, img::AbstractMatrix;
            board_bundles, config = FindBoardsConfig(), device = default_device(),
            gpu_index = nothing, matching_strategy = MutualNN(),
            exclude_polys = nothing, telemetry = nothing) -> Vector
find_boards(board_feature_dict, descriptor_network, frames; kwargs...) -> Vector{Vector}
find_boards(board_feature_dict, image_features; kwargs...) -> Vector

Find known boards in an image and estimate each one's homography or pose; returns one (uid, model, quality, scored) tuple per verified board.

The image method runs the whole pipeline once per image: detect blobs, adapt them to ellipses, canonicalize and describe them, then for every board match, fit (RANSAC + local optimization), gate on inlier count and appearance, and claim the board's image region so that no detection serves two boards.

Arguments

  • board_feature_dict: Dict(uid => features) of the gallery boards' descriptors, as returned by insert!(::BoardGallery, board_paths, network) (BoardGallery). Only these boards are searched for.
  • descriptor_network: a DescriptorNetwork (or the path of its ONNX file), the same network that described the gallery.
  • img: a grey image (AbstractMatrix, e.g. Gray.(load(path))). Give a vector of frames to run each independently with the gallery staged once. Give features from extract_image_features to skip the image stages.

Keywords

  • board_bundles (required): Dict(uid => BoardBundle) for every board in board_feature_dict (load_board(path).bundle). Polarity, cutoff and the board outline used for spatial claiming come from them.
  • config = FindBoardsConfig(): every pipeline setting (FindBoardsConfig). config.geometry selects the estimator: HomographyGeometry (no camera), PoseGeometry(camera) (calibrated P3P) or RadialHomographyGeometry(image_size) (unknown radially distorted camera). Build it from a TOML file with FindBoardsConfig(path; camera).
  • device = default_device(): the KernelAbstractions backend for detection, adaptation and description — KA.CPU(), or CUDABackend() once CUDA is loaded (the default picks the GPU when one is functional).
  • gpu_index = nothing: a prebuilt GalleryIndex of the gallery on device; built per call when nothing. Build it once to reuse across images.
  • matching_strategy = MutualNN(): the first matching phase's nearest-neighbour rule (a permissive KnnMatch(3) cleanup phase follows).
  • exclude_polys = nothing: image polygons whose detections are excluded before matching (regions already claimed elsewhere).
  • telemetry = nothing: a Telemetry sink that records per-stage diagnostics.

Returns

A vector with one (uid, model, quality, scored) tuple per accepted board, in acceptance order:

  • uid: the board's 3-character uid (the corner glyphs, a key of board_bundles).
  • model: with HomographyGeometry, the homography mapping the board's :world plane (mm, z = 0) to image pixels. With PoseGeometry, the board → camera pose (model.R, model.t in mm). With RadialHomographyGeometry, the (H, k) division-model fit.
  • quality: the fit's RANSAC score.
  • scored: the correspondences (board blob → image detection) with their posterior weights in scored.weights; count(is_map_inlier, scored.weights) is the inlier count.

See also

track_boards (video), FindBoardsConfig, BoardGallery, DescriptorNetwork.

source
find_boards(board_feature_dict, descriptor_network,
            frames::AbstractVector{<:AbstractMatrix}; kwargs...) -> Vector{Vector}

Batch entry point: run board detection on a SEQUENCE of frames with one-time setup amortization — the gallery GPU index (and each frame's detection plan) is built once and reused. Per-frame results are independent (no temporal association — see track_boards for that); element i is exactly what find_boards(..., frames[i]) returns.

source
find_boards(board_feature_dict, image_features::StructArray{<:DescribedFeature};
            kwargs...) -> Vector

Match pre-extracted image features against all boards, estimate geometry, gate on inlier count + appearance, and spatially claim/suppress. Runs round-based spatial suppression: every round fits all live boards on the current claim state, commits the single best, removes it from the gallery, and claims the detections inside its projected quad; surviving boards re-resolve their matches against the new claim state and refit, until a round accepts nothing. Two matching phases run this loop — strict MutualNN, then a permissive KnnMatch(3) cleanup on the depleted pool.

Arguments

  • board_feature_dict: Dict{uid => StructArray{DescribedFeature}} of board features
  • image_features: Pre-extracted StructArray{DescribedFeature} from extract_image_features

Keyword Arguments

  • config: FindBoardsConfig. config.geometry selects the path — HomographyGeometry() (no camera) or PoseGeometry(camera) (calibrated P3P).
  • board_bundles: Dict{uid => BoardBundle} — required for spatial claiming and guided search (enforced with an ArgumentError).
  • device: KA device (KA.CPU() or CUDABackend())
  • gpu_index: Pre-built GalleryIndex for the device-resident board gallery

Returns (uid, model, quality, scored) for each verified board (IRLS weights in scored.weights), concatenated across phases.

BlobBoards.track_boards — Function
track_boards(board_feature_dict, descriptor_network, video_path::AbstractString; kwargs...)

Track boards through a video file. Opens video_path and streams it frame by frame — nothing is materialized, since the sequence method only ever enumerates its input.

This mirrors annotate_blobs and save_trace, which already take video paths directly; VideoIO is a hard dependency, so accepting one here costs nothing and saves every caller an openvideo + close dance.

source
track_boards(board_feature_dict, descriptor_network, images;
             board_bundles, config=FindBoardsConfig(),
             iou_threshold=config.track.iou_threshold,
             support_fraction=config.track.support_fraction,
             patience=config.track.patience,
             keyframe_every=config.track.keyframe_every, device=default_device(),
             gpu_index=nothing, on_frame=nothing)
    -> Dict{String, Vector{BoardDetection}}

Track boards across a sequence of images: motion-guided association plus a per-frame RANSAC over the associated correspondences (see the file header for the algorithm). Calibration (if any) lives in config.geometry.

  • iou_threshold: per-blob predicted↔detected ellipse IoU gate ([find_boards.track]; tolerates roughly ½σ of center prediction error but rejects wrong-octave scale).
  • support_fraction: fraction of predicted blobs that must associate for the warm bet to proceed to estimation.
  • patience: consecutive failed frames before a track stops being re-targeted every frame (it stays eligible for discovery keyframes).
  • keyframe_every: discovery cadence for boards not currently tracked (0 disables periodic discovery after frame 1). NB between keyframes only boards ALREADY tracked are searched for, so a board first appearing at frame k is not looked for until the next keyframe — correct for video, and the reason unrelated stills belong in find_boards instead.
  • gpu_index: prebuilt GalleryIndex, as on find_boards. Built here when omitted; supply one to reuse the staged gallery across several media instead of re-uploading it per call. When supplied, the INDEX defines which boards are matched — an index from a different gallery matches the wrong boards silently.
  • on_frame: a sink called on_frame(frame::TrackFrame) after every frame with that frame's record, pixels and configuration of record (a failing sink warns and tracking continues). Capture a replayable trace with trace = TrackTrace(); track_boards(…; on_frame = f -> push!(trace, f)).

Returns Dict{uid => Vector{BoardDetection}}; each detection's source records whether the frame was won by the :track association path, a targeted :init, or :detect.

BlobBoards.FindBoardsConfig — Type
FindBoardsConfig(; kwargs...)

Configuration for find_boards pipeline. The geometry field (HomographyGeometry or PoseGeometry) groups the per-estimator knobs (outlier half-width, min inliers) and determines which path runs.

Detection

  • detect::DetectConfig = DetectConfig(): Detection configuration (single source of truth for detect_blobs parameters across all backends).
  • max_detections=typemax(Int): post-detection response-rank cap. On the grouped image path it is applied PER POLARITY GROUP (after _polarity_subset), so a mixed dark+light board set can process up to 2× this many detections in total — see _detect_for_boards for why the shared detection stage must stay uncapped. Single-polarity sets (every real set) behave exactly like a detect_blobs(; max_detections=…) cap.

Adaptation (blob fitting)

  • adapt::AdaptConfig = AdaptConfig(): Adaptation configuration

Geometry estimator

  • geometry::GeometryConfig = HomographyGeometry(): per-estimator RANSAC + inlier-gate knobs. Use HomographyGeometry() for the no-camera path or PoseGeometry(camera) (the camera lives in the geometry) for the calibrated P3P path.

Matching

  • min_similarity=0.6: Minimum descriptor cosine similarity. The derived gates move with it: phase 2's permissive gate (_phase2_similarity, 0.1 below), which is not configured separately so it cannot drift apart under a sweep. The agenda counts every resolved match — there is no second similarity bar (see _n_resolved_matches).

Appearance verification (mandatory)

  • verify_similarity=0.6: an inlier correspondence "agrees in appearance" when its gallery and image descriptors reach this cosine similarity. Deliberately NOT named min_similarity — a different quantity at a different stage that happens to share the value (see appearance_support in verify.jl).
  • min_appearance_support=0.5: minimum fraction of a candidate board's inliers that must agree in appearance for the board to be accepted.

Geometry cannot make this call. Guided association is descriptor-blind, and at measured detection densities (13,844/MP, 5 px band) 66% of arbitrary positions have SOME detection in range — a fabricated board fills its inlier set geometrically, so counts and fractions satisfy it. The inliers' APPEARANCE separates real from fabricated with zero measured overlap (real ≥ 0.993 support, false = 0.0 at a 0.8 sim gate; see verify.jl). This gate replaced the geometry structs' min_inlier_fraction (a proxy for the same attack, removed 2026-08-13).

verify_similarity was calibrated DOWN twice on the 260527 corpus (2026-08-14), each time because the real population's frontier sat under the gate while false boards never came near it (median 0.07–0.37): 0.8 → 0.7 on the strided 12-frame slice — distant real boards carry median inlier sims 0.73–0.80; 0.8 rejected 8 GT-verified real boards. 0.7 → 0.6 on the FULL corpus — the inter-slice 2–3 m frames the stride never sampled dip to median sims 0.66–0.71, so 0.7 gated 13 more real csponds (probe: support 0.30–0.47, deterministic). At the default support of 0.5 the gate is exactly a MEDIAN test, so the bar must sit under the real population's frontier median. NB appearance is structurally blind to POSE FLIPS (correct correspondences, mirrored rotation): that is resolve_pose_ambiguity's job, not this gate's — and loosening this bar re-admits flipped poses along with good ones.

Reproducibility

  • ransac_seed=0x0b10b5eed: base seed for the per-fit RANSAC streams (Xoshiro(ransac_seed ⊻ board uid) — see _fit_rng). Identical inputs give identical results, independent of thread scheduling, call order, and ambient RNG state; sweep it only to MEASURE fit-stage RNG sensitivity. CUDA feature extraction remains nondeterministic (adapt's atomic pixel slots), so end-to-end reproducibility is "given features".

Every field is CONCRETE by design: this config is read inside the per-board fitting loop, so an abstract field (adapt::AdaptConfig, geometry) would force boxing and dynamic dispatch on every access. Keep it that way when adding fields.

Overriding one knob

The struct is immutable and find_boards has no per-knob keyword — you supply a whole config. To change one setting, use Accessors.@set, which reaches nested fields and rebuilds only what changed:

Accessors is NOT a dependency of BlobBoards — add it to your own project (pkg> add Accessors). No library code is needed for this to work: ConstructionBase's generic setproperties already handles these structs.

using Accessors                       # your dep, not BlobBoards'cfg = FindBoardsConfig("configs/default.toml"; camera)cfg = @set cfg.detect.peak_threshold = 0.02cfg = @set cfg.detect.upsample = false

This works through ConstructionBase's generic setproperties, which is correct here only because every one of these structs is a plain @kwdef with no inner constructor — so its positional constructor matches its field order. Adding a validating inner constructor to FindBoardsConfig, DetectConfig, AdaptConfig or a GeometryConfig silently breaks the override idiom; test/test_config_toml.jl gates that, including the type-changing case (@set cfg.detect.nms = EllipseNms(...), which alters a type parameter).

Sweeps should override rather than re-list: a hand-built FindBoardsConfig in a driver duplicates the knobs of the config of record, and the two drift. See bmvc2026/scripts/tune_invariance.jl.

BlobBoards.PoseGeometry — Type
PoseGeometry(camera; outlier_halfwidth=5.0, min_inliers=6, local_optimization=StudentTUniformIrls())

Calibrated P3P estimator config. Holds the camera (a CameraModel carrying the lens/distortion model used to undistort the image). The camera lives here — not as a separate find_boards argument — so calibrated-ness is encoded in one place and illegal camera/geometry mismatches are unrepresentable.

undistortion selects where the pose is measured: :none (the default) detects, adapts and describes on the RAW image and the estimator verifies through the FULL camera — RANSAC scoring, the Student-t M-step and the Welsch lift all measure the reprojection through the lens in the pixels the detector produced (RobustVisualGeometry ≥ 0.19.9), and guided association transfers each blob's conic through the plane homography exactly and the lens's affinity at its centre (transfer_ellipse(::Camera, _)). :global undistorts the IMAGE (VGC's fused warp) and runs the whole pipeline on the result through the pinhole twin — the historical path, and what the BMVC runs used (their configs state it). Why :none: a residual in the undistorted plane is the detection error magnified by the lens's inverse slope — 84× at the rim of an 8 mm fisheye — so a 5 px gate there rejected every rim point; in raw pixels the gate means what it says everywhere.

3 is the geometric minimum for p3p; the default 6 leaves three outlier-tolerated points above the minimal sample. P3P is 2 DOF tighter than homography, so it needs one fewer support point than the homography path (mininliers=7). (The gate is INCLUSIVE — `nin >= mininliers` — since 2026-08-11; the default went 5 → 6 in the same change, keeping the effective tuned threshold: a 5-inlier P3P fit against a 50-board gallery measured as a false accept on DSC02847.) BlobBoards.prepare_image_features — Function
prepare_image_features(descriptor_network, img;

The camera (for the BrownConrady undistort) is read from config.geometry — PoseGeometry carries it, HomographyGeometry has none (undistort becomes a no-op).

Detect blobs in an image via the KernelAbstractions ASIFT pipeline, then apply a BB-side response-rank cap.

BlobBoards.AdaptConfig — Type
AdaptConfig(; kwargs...)

Configuration for blob adaptation (paraboloid fitting).

IRLS

  • spatial_weighting::Bool = true — adaptive spatial weights from current shape
  • cutoff::Float64 = 2.0 — pixel window in units of σ
  • max_irls_iter::Int = 20 — maximum IRLS iterations
  • rtol::Float64 = 1e-6 — relative parameter convergence threshold

Filtering

  • min_intensity::Float64 = 1e-6 — minimum inverted intensity to include pixel
  • max_scale_fraction::Float64 = 0.1 — skip detections whose σ exceeds this FRACTION of the image's √area, i.e. σ > f·√(W·H). A resource guard: a blob's fitted support is ~(2·cutoff·σ)² pixels, so an unbounded σ is an OOM. It is a fraction rather than a pixel count because the same absolute cap means different things on different sensors — 200 px was ~5.8% of √area at 12 MP and larger than the whole frame at VGA, so an absolute value could not transfer across cameras. √area (the side of the equivalent square) is used rather than min(W,H) or the diagonal so the cap is aspect-neutral.
  • max_scale_ratio::Float64 = 4.0 — reject if adapted σ / detection σ exceeds this
  • scan_padding::Float64 = 1.0 — per-blob scan box halfwidth = cutoff · scan_padding · σ (decoupled from max_scale_ratio)
  • max_clip_ratio::Float64 = 0.2 — reject if blob is clipped by image boundary
  • max_aspect_ratio::Float64 = 10.0 — reject if ellipse axis ratio exceeds this

Accumulation and the 6×6 solve run in Float64 wherever the backend supports it (Float32 on Metal); per-pixel staging is pinned Float32. (store was deleted 2026-09: inert since the KA port — no kernel read it.)

BlobBoards.EllipseNms — Type
EllipseNms(; cutoff=2.0f0, band_octaves=1.0f0, band_reach=1)

Mahalanobis-footprint cross-warp NMS. Two ASIFT features collide if their cutoff-σ footprints share a pixel; the lower-response one is dropped. Respects ellipse shape. Suppression is SCALE-BANDED: a feature can only be suppressed by one whose geometric-mean scale band ⌊log2 √det S / band_octaves⌋ is within band_reach of its own (1 octave ± 1 ⇒ scale ratio < 4), so board-sized extrema and tilted-warp streaks cannot erase the small blobs inside them. band_octaves = 0 restores the whole-pool rule.

Training Pipeline

BlobBoards.build_tracks_for_sequences — Function
build_tracks_for_sequences(board_dir, descriptor_model_path, video_dir; kwargs...)
    -> output_path

Build multi-modal training tracks for every media file in video_dir against every board .json in board_dir, accumulating into $output_name.tracks.

Videos (.mp4, .mov, .avi, .mkv, .m4v) are sampled into frames; photos (.jpg, .jpeg, .png, .tif, .tiff, .bmp) are treated as a single frame. A photo yields at most one observation per tracked blob (paired against its GT anchor via the anchor sequence); n_frames/stride are ignored for photos.

For each media item the boards are detected + tracked across frames (track_boards), then blob correspondences are established per frame by transferring the board's GT blobs through the estimated world→image homography and validating by IoU. Each surviving track stores, per observation, a single patch view (patch_type) at a single scale, a per-pixel board∩in-frame mask, and the per-frame affine shape. Tracks hold only tracked observations; the GT anchor patches are not included.

One .tracks file therefore holds exactly one patch type at one scale — the output_name is auto-suffixed _<patch_type>_s<scale> so logpolar/cartesian runs (or different scales) never collide in the same file.

Each patch carries a masks companion (same P×P×N shape): 1 where the pixel back-projects onto the board's world rectangle AND onto a real image pixel, 0 over off-board background, image edges, and perspective-warp gray-fill voids. Confuser (untracked) patches carry an in-frame-only mask (no board); anchor patches carry an in-frame mask against the rendered board image.

Two independent augmentations may fire per frame, both before extraction: a resolution-loss down/up-resample (probability p_downsample, coordinate- preserving) and a perspective warp (p_perspective) that strengthens the primary board's real foreshortening. The perspective warp composes its homography into every board's world→image map, so correspondences stay valid on the warped frame. A third, blur_sigma_max, adds Gaussian blur and is OFF by default.

Additionally, one anchor sequence per board is written, named by the board uid (rather than $(video)_$(uid)), holding every GT reference blob keyed by the same blob_track_id used by the per-video tracks — so each track's GT anchor is recoverable by id.

Boards and their gallery features are keyed by uid (the board's SHA-256 hash, as produced by load_board) — the same key track_boards returns — so lookups stay consistent end to end.

Already-processed sequences present in an existing output file are skipped (both $(video)_$(uid) video sequences and $(uid) anchor sequences), so the call is resumable.

Keyword Arguments

  • n_frames / stride: frame sampling (mutually exclusive; default = every frame)
  • iou_threshold=0.6: minimum symmetric IoU for a valid blob correspondence. Kept fairly strict: a board's homography extrapolates its grid over nearby near-coplanar boards in a stack, and a loose threshold lets the dense fractal pattern produce coincidental cross-board false matches. 0.6 removes almost all of them (a handful survive per board vs hundreds of true matches) at a modest recall cost on fully-visible boards.
  • max_detections=typemax(Int): per-frame detection cap (set it, e.g. 5000, on high-resolution footage to keep the GPU descriptor-match GEMM in memory)
  • max_image_pixels=nothing: optional cap on each frame's total pixel count (aspect ratio preserved), e.g. 3840*2160 (≈8.3 MP). The default keeps the native resolution. The detector allocates a full image pyramid sized to the frame, so set this on high-res stills (a 24 MP phone photo). Applied at read time so detect/track/adapt/canonicalize all share one coordinate system.
  • min_inliers=20: board-acceptance threshold applied AFTER tracking — a tracked detection is kept only when its inlier count reaches this. It is a post-filter on track_boards' output, not a HomographyGeometry setting; the tracker itself runs the config-of-record gate (min_inliers = 7).
  • patch_type=:logpolar: the single patch parameterization written to this file — :logpolar, :cartesian, or :original (see canonicalize).
  • scale=32: the single patch scale — half the patch width/height in units of σ. Patches are stored P×P×N; patch_type/scale are recorded as attributes on each sequence's tracks group.
  • confuser_factor=1.0: cap total confusers (untracked patches) at confuser_factor × tracked patches, sampled at random. Each confuser stores the chosen patch view + its in-frame mask under untracked/{patches,masks}. Supply Inf to keep all confusers (no cap).
  • debug_dir=nothing: when set, save one PNG per processed frame into this directory — the frame the detector ran on, with every board detected in it overlaid in its own color: that board's matched GT blobs as projected ellipses plus its projected board rectangle. Colors are stable per board across frames and printed once at run start. Purely diagnostic; nothing disables it.

Turning off the memory caps (large GPU)

Three knobs bound GPU/host memory on constrained hardware; on a large GPU set them wide to process everything:

  • max_detections=typemax(Int) (default) — no per-frame detection cap. Lower it (e.g. 5000) only if the all-boards × all-detections match GEMM OOMs.
  • max_image_pixels=nothing — keep native frame resolution (the default).
  • confuser_factor=Inf — keep every confuser patch.
  • supersample=1: anti-aliasing supersample factor forwarded to canonicalize for every patch view and scale. At the large scales (64/96/128) one output texel spans many source pixels, so the default single-tap sampling aliases; >1 samples on a finer grid and box-averages down. Cost scales as supersample² and is paid at every scale, including the small ones that do not alias. 3–4 is the quality sweet spot.
  • p_downsample=0.75: probability of the resolution-loss augmentation firing on a frame (down- then up-sample to simulate blur/scale loss; conditional on firing, the three tiers 0.5×/0.25×/0.125× are equally likely). Independent of the perspective warp — both can fire on one frame. 0 disables it.
  • p_perspective=0.5: probability of applying the perspective augmentation to a frame. It warps the frame with a homography that strengthens the primary (highest-quality) board's existing foreshortening, keeping the board centroid fixed, and composes the same warp into every board's homography. Independent of the resolution-loss augmentation — both can fire on one frame. 0 disables it.
  • perspective_strengthen_max=1.0: upper bound of the strengthening factor. The board plane's vanishing line is scaled by 1+γ with γ drawn uniformly from [0, perspective_strengthen_max], so 0 reproduces the frame's real perspective and larger values exaggerate it along the board's own tilt.
  • perspective_jitter_max=0.1: upper bound of the extra random-direction tilt added on top of the strengthening, in a board-normalized frame (world extent → [-1,1]²), so the magnitude is unit- and board-size-invariant.
  • blur_sigma_max=0: upper bound of the Gaussian blur augmentation. When positive, every frame is blurred with σ ~ U[0, blur_sigma_max] (px) before extraction; 0 disables it. Unlike the other two augmentations this one is unconditional once enabled — there is no separate probability — so it shifts the whole training distribution rather than sampling from it. Independent of the resolution-loss and perspective augmentations.
  • write_anchors=true: write one per-board GT anchor sequence (named by uid) before processing media. Set false to skip them — useful for false-board diagnostics that only need the <media>_<uid> tracked sequences, since the anchor galleries are large and slow to compress.
  • writer_buffer=1: depth of the async-writer queue. A single background task owns the output file and does all HDF5 compression/writes while the GPU thread builds the next sequence (overlap needs julia -t ≥2). Larger values give more slack but hold more finished (large) sequences in memory; 0 = rendezvous.
  • async_writer=true: overlap HDF5 compression with GPU compute via the writer task above. Set false to write synchronously on the GPU thread (no overlap) — for -t 1 / memory-constrained runs.
  • output_dir=".", output_name="tracks": output $output_name.tracks location
  • backend=default_device(): compute backend for adapt/canonicalize/describe (CUDABackend() when CUDA is loaded, otherwise KA.CPU())

BlobBoards.build_absolute_tracks — Function
build_absolute_tracks(boards, model, video_path; board_feature_dict,
                      board_bundles, kwargs...) -> output_path

Build multi-modal tracks for one video against a set of boards (see build_tracks_for_sequences for the higher-level driver).

boards is a Dict{uid => board} (each a load_board NamedTuple with an extra image field), board_feature_dict a Dict{uid => features} and board_bundles a Dict{uid => BoardBundle} — all keyed by the same uid that track_boards returns. Sampling, filtering, patch and augmentation keywords (n_frames/stride, iou_threshold, max_detections, max_image_pixels, patch_type, scale, confuser_factor, supersample, p_downsample, p_perspective, perspective_strengthen_max, perspective_jitter_max, blur_sigma_max) behave as documented on build_tracks_for_sequences, which forwards them here. patch_size=64 is local to this function. output_name is used verbatim (the higher-level driver adds the _<patch_type>_s<scale> suffix). sink receives each finished sequence as (name, tracks, confusers, is_anchor); the default writes it synchronously. on_view_stats, when given, receives this media item's viewing-angle records once, as on_view_stats(stats::Vector{ViewAngleStat}) (sorted by (uid, frame_idx)) — the driver collects them into its run-wide chart.

BlobBoards.save_tracks — Function
save_tracks(path, tracks; sequence_name, untracked=nothing, patch_type=nothing,
            scale=nothing, is_anchor=false) -> path

Save tracks (and optionally untracked/confuser patches) to a .tracks file (HDF5 format). Each media item is stored as a separate sequence group so new items can be appended incrementally to the same file.

HDF5 layout

Dict (single-mode — one patch type at one scale, written by build_absolute_tracks / save_board_anchors):

  • /sequences/<name> — group attribute is_anchor (UInt8, 1 for the per-board GT anchor sequences, 0 for the per-media tracked sequences)
  • /sequences/<name>/tracks/patches — (P, P, N) float32, chunked+compressed
  • /sequences/<name>/tracks/masks — (P, P, N) float32; per-pixel board∩in-frame mask (1 where the patch pixel lands on the board sheet AND on a real image pixel; 0 over off-board background, image edges and perspective-warp voids)
  • /sequences/<name>/tracks/affine_shapes — (2, 2, N) float32
  • /sequences/<name>/tracks/frame_id — (N,) int32; source frame of each observation. Tracked sequences only (GT-anchor sequences omit it).
  • /sequences/<name>/tracks/homographies — (3, 3, F) float64; ONE world→image homography H_wi per frame the board was detected in (F frames, not N observations). Tracked sequences only.
  • /sequences/<name>/tracks/view_angles — (F,) float64; per-frame viewing obliquity in radians (0 = fronto-parallel, → π/2 edge-on), from the local affine tilt of H_wi at the board centroid (intrinsics-free; metric because the board is square). Aligned with homographies.
  • /sequences/<name>/tracks/homography_frame_ids — (F,) int32; the frame index of each homographies/view_angles column. Join an observation to its pose via frame_id → this table.
  • /sequences/<name>/tracks/track_id, n_tracks, track_lengths
  • /sequences/<name>/tracks — group attributes patch_type (string) and scale (float64)
  • /sequences/<name>/untracked/patches, untracked/masks — (P, P, M) float32 (present only when confusers were supplied)

A second, Vector{Track} layout used to live here for build_tracks; both it and its reader went with that pipeline (2026-08-19).

.tracks files

.tracks is plain HDF5 and is not registered with FileIO — the format"BlobBoardTracks" hooks were removed in 2026-08 (the format had in fact never been registered, so FileIO.load("x.tracks") never worked). BlobBoards.media_resolution — Function
media_resolution(path) -> Size2

Frame size of the image or video at path, as a Size2 (width, height).

Videos report it from stream metadata without decoding; images fall back to a decode, since Julia's image stack exposes no general header-only probe. Costs ~0.6 s for a video and ~0.8 s for a 24 MP still, so it is a preliminary probe, not something to call per frame.

Size2 rather than a tuple ON PURPOSE: VideoIO.out_frame_size is (width, height) while Base.size is (rows, cols), and a bare tuple cannot say which it holds — that ambiguity produced a real transposition bug here. The named fields make both branches state the same thing.

BlobBoards.group_by_resolution — Function
group_by_resolution(paths; probe = media_resolution)
    -> Vector{Pair{Size2, Vector{String}}}

Group media by frame resolution, largest group first, order preserved within each group.

Process each group together and call VisualGeometryFeatures.clear_asift_plans!() at the boundary: one plan build per group instead of one per resolution change. Also stage the gallery once (GalleryIndex) outside the loop and supply it as gpu_index — it is independent of resolution, so rebuilding it per medium re-uploads the whole descriptor set for nothing.

ORDER IS SAFE AT MEDIA GRANULARITY ONLY. Never reorder frames within one medium: track_boards predicts each frame from the previous two, so shuffling a sequence destroys the temporal association. Every frame of a video shares one resolution anyway, so a video is intrinsically one group.
