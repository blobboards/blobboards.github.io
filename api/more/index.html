Extensions, Tooling and Internals

The rest of the public surface: the functions the package extensions provide (plots, the Python interface, the Lux backend, training), the pipeline's configuration and stages, traces, and the training-data tooling. Each name is reached as BlobBoards.name unless it is exported.

BlobBoards.BlobBoards — Module
BlobBoards

Generate calibration boards with blob patterns for computer vision applications.

Quick Start

using BlobBoards   # units (mm, px, dpi, …) are re-exported# Generate a PDF board with standard paper sizebundle = blob_board("A4"; blob_sizes=(4.0mm, 0.2short_side), cutoff=2.0, seed=0x1234, dir="./output")# Generate a pattern with logical dimensionspattern, blobs, config = blob_pattern(800, 600; blob_sizes=(12px, nothing), cutoff=2.0, seed=0x1234)# Extract blobs from saved filesbundle, _ = BlobBoards.load(BlobBoards.BoardBundle, "blob_board.json")b = blobs(bundle, :pattern; units=mm)  # Physical unitsb = blobs(bundle, :canvas; density = 300dpi)   # Pixel units, at a density

Key Interface Notes

  • blob_board: blob_sizes = (min, max) are printed disc diameters in physical units, both required (e.g., suggest_blob_sizes(600dpi, "A4"), or (6mm, 38mm)); stored as σ in points
  • blob_pattern: blob_sizes = (min, max) are disc diameters in logical units (e.g., (12px, nothing))
  • blobs(bundle, reference_frame; units=px, density): Extract blobs with specified frame and units

Coordinate Specifications

BlobBoards uses three types of coordinate specifications:

  • Image origins (:colmap, :opencv, :julia): Pixel coordinate conventions
  • Reference frames (:pattern, :board, :canvas): Spatial origins on boards
  • Coordinate systems (:pixel, :physical, :world): Unit systems for transforms

Blobs are stored internally in :colmap convention. Use EuclideanMap(PixelFrame{:colmap}, PixelFrame{:julia}) to convert.

Features

  • Deterministic patterns from seeded configurations
  • Physical units via FlexUnits (mm, inch, dpi, etc.)
  • Printable boards (PDF) or training images (PNG) with ruler or blank frames
  • JSON serialization for exact reproduction
  • Blob extraction with multiple coordinate conventions and reference frames
  • World coordinates for 3D pose workflows
  • Visualization helpers for Makie backends
  • Bit-exact reproducibility across Julia and Python interfaces

BlobBoards.AbstractDescriptorNetwork — Type
AbstractDescriptorNetwork

Abstract type for descriptor models. Subtypes must implement:

  • describe(model, patches) -> Matrix{Float32} (N×D, L2-normalized)
  • network_hash(model) -> String (unique identifier for cache invalidation)
  • patch_size(model) -> Int (the input resolution the network requires)

Batching is a property OF THE MODEL, not of the call (max_batch sizes its CUDA arena).

source
BlobBoards.patch_size — Function
patch_size(model::AbstractDescriptorNetwork) -> Int

The canonical patch resolution the network takes, as a property OF THE NETWORK rather than a configured number.

It used to be a [descriptor] patch_size key in the run config, which restated something the checkpoint already fixes. That was redundant rather than dangerous — a mismatch is refused by the backend — but it was refused late: patch_size is part of the gallery cache key, so a wrong value first missed the cache and re-extracted the whole board set, and only then failed at the first describe. Deriving it makes the disagreement impossible instead of merely detectable.

source
BlobBoards.descriptor_network_path — Function
descriptor_network_path(run_config) -> String
descriptor_network_path(path::AbstractString) -> String
descriptor_network_path() -> String

Absolute path to the descriptor checkpoint named by a run config's [descriptor] model key, resolved against data_dir.

This is the ONLY way a run should name its network. It replaced a DEFAULT_DESCRIPTOR_MODEL constant in this package plus a LocalPreferences key plus ENV["BLOBBOARDS_DESCRIPTOR_MODEL"] plus per-driver BB_ONNX — four mechanisms, of which the library-level constant was the worst: a package asserting the filename of one lab's checkpoint, which meant anyone installing BlobBoards got a default pointing at a file they had never had, and two paper artifacts silently ran a different network from the paper's main sweep.

data_dir() stays in LocalPreferences because where the data lives is genuinely per-machine. Which network to use is a property of the experiment, not the machine — which is exactly why the preference mechanism was the wrong scope for it.

The key is required. There is no default: a run that does not say which network it used is a run whose results cannot be reproduced.

TWO source forms, selected by the TOML value's type:

model = "models/x.onnx" # STRING: data_dir-relative — the FROZEN form. Bytes come from the local primary copy or the DOI'd Zenodo assets tier; experiment configs use this so the paper's network is pinned to an immutable record.

model = { artifact = "x" } # TABLE: Pkg artifact — the DISTRIBUTION form. artifact names an entry in the package-root Artifacts.toml, a catalog of every published network (lazy entries, tarballs in a numbered version of the BlobBoards Zenodo record, sha256 + git-tree-sha1 verified). The first run fetches the tarball into Julia's shared content-addressed artifact store; every later run resolves locally. The catalog cannot float: an entry IS a pinned hash, so a config always means the same bytes — newer weights are published as a NEW catalog entry and adopted by editing the config's artifact name, a git-tracked one-line change on each side.

BlobBoards.TrackConfig — Type
TrackConfig

The tracker's knobs — [find_boards.track] in the config of record; every track_boards keyword defaults from here and overrides per call. Until 2026-09 these four sat as bare keyword literals on track_boards, so a tracking run's sidecar could not name them.

  • iou_threshold: per-blob predicted↔detected ellipse IoU gate for the warm association (ellipse overlap at the board's own cutoff).
  • support_fraction: fraction of the predicted blobs that must associate for the warm bet to proceed to estimation.

  • keyframe_every: discovery cadence for boards not currently tracked; 0 disables periodic discovery after frame 1.

BlobBoards.read_run_config — Function
read_run_config(path; tables = ()) -> (; config_toml, find_boards, experiment, gallery, descriptor)

Read the whole run config, not just the [find_boards] table: config_toml is the raw parsed file (for a provenance sidecar), and the named fields are its top-level tables, defaulting to empty. Drivers use this to get the dataset, subsets and descriptor model from the same file that configures find_boards, so there is one thing to supply and one thing to record.

OWNERSHIP AND VALIDATION: unknown TOP-LEVEL tables are refused (a typo'd [descripter] used to make every knob in it a silent no-op), and the package-owned [descriptor] table is key-checked (model only; the retired patch_size warns — the graph declares it). [experiment] and [gallery] are DRIVER-owned free-form tables: the research drivers define their keys, and the package deliberately has no opinion on them. So is [inputs], the paper projects' [inputs.<id>] statement of what a run reads (VisualGeometryToolkitEval's convention: tier, path, provenance, sha256). A driver that keeps further top-level tables of its own names them in tables; they are admitted, not checked, and read from config_toml. (The board and pattern authoring defaults are configs/authoring.toml's, never a run config's: [blob_board] there is refused.)

BlobBoards.BlobDetection — Type
BlobDetection{T}

Type alias for a Detection with an EllipticFrame and metadata containing:

  • id::Int — index into the original detection vector
  • the blob's adaptation outcome (VisualGeometryToolkitCore's termination record):
    • retcode::ReturnCode.T — Success (converged at rtol: the blob's convergence is successful_retcode(det.retcode), §14, not a field of its own), MaxIters (capped at max_irls_iter: unconverged), Failure (the shape gate refused a step: rejected), InitialFailure (it refused the first step from the seed);
    • stop_rule::StopRule — IncrementSize (the IRLS step below rtol, Estimation's irls_termination), IterationCap or ShapeGate;
    • rejection::Symbol — why the shape gate refused: :not_peak (the fitted paraboloid is not concave) or :aspect_ratio (beyond max_aspect_ratio); :none otherwise.

Capped and rejected blobs are returned, flagged; count_unconverged and count_rejected count them.

Access fields via property forwarding: det.center, det.id, det.retcode.

BlobBoards.match_boards — Function
match_boards(strategy, galleries, features; index, backend, min_similarity)
    -> Dict{uid, Vector{NNMatch}}

Descriptor matching of one image's features against a board gallery (uid => board features), keyed per board: one entry per gallery key, empty vectors included. index is a GalleryIndex built once over the board set and reused across images.

ONE path, every strategy: the board set is matched as ONE gallery and the rows are split back. There is no per-board matching mode, because the per-board question is the wrong one. nn_match_stacked's reverse test is BLOCK-LOCAL — documented as "per gallery the result is identical to matching that gallery alone" — which is the right contract for N INDEPENDENT galleries and not what this pipeline asks: a detection belongs to exactly one board, so mutuality has to hold over the whole board set. Asked per board it is N independent questions and one detection can win several — measured on one 12 MP fisheye frame, 629 detections were claimed by more than one board, 40% of all matches were duplicates (1685 of 4209), and they fabricated 33 boards sitting at the min_inliers floor with grossly wrong poses. Through the stack the same frame gives 2496 matches, 2496 unique, zero duplicates.

KnnMatch used to take a second, per-board staging on the grounds that it has no reverse test to correct. It does not need one: its reduction (_ka_top4_rows!) is per gallery ROW over all features, so it returns the same matches under either blocking, and the per-board staging was only a duplicate copy of the same descriptors (see GalleryIndex).

galleries selects which boards may be returned — the engine's pool SHRINKS as boards are accepted, while the index stays over the full board set. A detection whose global best belongs to an accepted board is therefore dropped rather than handed to its runner-up, which is the one-detection-one-board rule the claiming enforces anyway.

BlobBoards.guided_search — Function
guided_search(H, bundle, image_features;
              min_iou, keep = Pair{Int,Int}[],
              rtree, det_ells, wdiscs, wregions) -> StructArray

Final-fit correspondence builder. Project every world blob of bundle's pattern into the image through H (build it with _world_to_image) and associate it by OVERLAP alone: its candidates are the detections whose ellipses' bounding boxes intersect the bounding box of the projected ellipse (an R-tree query; both ellipses at the blob's rendered boundary, region(·, cutoff(bundle)), the same convention annotate_blobs uses for GT labeling), and it is associated with the candidate of highest exact ellipse IoU when that IoU is ≥ min_iou. The IoU is the only acceptance criterion: there is no radius, the projected ellipse bounds the search.

The IoU gate is purely geometric — descriptors are not consulted. It is what rejects confuser boards: a wrong board can be smeared onto a detection cluster center-wise, but its blobs' projected scales and shapes won't agree with the adapted frames, so they fail the overlap check. Returns a world-disc ↔ detection ScoredCorrespondence set for a posterior-weighted refit via _find_model (one-to-one, best overlap first), recovering pattern blobs the descriptor matcher missed without admitting smears.

H is the guided TRANSFER: a HomographyMap on the projective arms, a RadialHomography on the radial one, where the conic goes through the homography exactly and only the undistortion is linearised (_guided_transfer), or a VisualGeometryToolkitCore PosedCamera (a camera model and a board pose), where the conic goes through the plane homography exactly and the lens's affinity is taken at the transferred centre.

keep (world blob => detection index pairs) are admitted first and unconditionally. The remaining keywords are hoistable context, each computed here when absent: det_ells the detections' ellipses at the board's rendered boundary, rtree an index over THOSE ellipses (detection_rtree(det_ells), whose skip keeps claimed detections out), and wdiscs/wregions the board's world blobs and their regions. It is not a bare point map because the work here is CONIC transfer, not point transfer — the IoU gate tests a blob's projected shape, so the map has to carry the conic, not just its centre.

The transfer is one of the three a model hands back (_world_to_image): a HomographyMap (the homography arm), a PosedCamera (the pose arms, any lens: Core's transfer_ellipse(::PosedCamera, _) — the plane homography of its pinhole twin exactly, then for a distorting lens its affinity at the transferred centre, behind a cheirality test), or a RadialHomography (the radial arm: the conic through H exactly, the undistortion linearised).

transfer_ellipse rather than the bare H(ellipse) callable, because a projective map does NOT always send an ellipse to an ellipse: when the conic crosses the line at infinity the image is a hyperbola or parabola. The callable returns a conic matrix; transfer_ellipse classifies it and returns nothing for the degenerate cases (and behind the camera), which _guided_candidates skips.

BlobBoards.detection_rtree — Function
detection_rtree(detections; skip = nothing) -> SpatialIndexing.RTree

An R-tree over the detections, indexed by position j. It indexes their centroids (detections a vector of points: point rects, the warm track's radius queries) or over their ellipses (detections a vector of Ellipses at a board's rendered boundary: each ellipse's bounding box). The ellipse form is the rtree that guided_search queries: a projected blob's candidates are the detections whose boxes intersect its own.

skip (a BitVector over the detections) leaves the detections already claimed out of the index, so they can never be re-associated; the engine instead builds one index per phase and hands guided_search the claim mask as its skip, which gives the same candidates. The codebase's standard spatial index (pattern.jl collision detection, annotate.jl IoU matching).

BlobBoards.symmetric_iou_match — Function
symmetric_iou_match(H_ij, frames_i, frames_j;
                    cutoff=2.0, iou_threshold=0.3) -> Vector{TrainingPair}

Symmetric matching of the detections of two frames related by the homography H_ij, scored by the IoU of their cutoff-scaled boundary ellipses.

SYMMETRIC: a pair is kept only when both directions succeed. Forward, the detection of frame i, transferred through H_ij, finds its best-IoU match among frame j's detections. Backward, that match, transferred through H_ij⁻¹, overlaps the original detection. Each IoU must reach iou_threshold.

For each detection in frame i:

  1. Transfer its boundary ellipse to frame j via H_ij
  2. Find best IoU match among frame j detections
  3. Transfer that match back to frame i via H_ij⁻¹
  4. Check IoU with original detection
  5. Accept if min(forwardiou, backwardiou) ≥ iou_threshold

One deterministic sweep: no sampling, no iteration (an algorithm name, not a find: CLAUDE.md's verb conventions).

Each row is one angle bin: the mean GT blobs matched per board-frame (the bar), the recall against the board's blobs visible in those frames, the mean total frame detections, and the bin's board-frame count. Empty bins are skipped.
